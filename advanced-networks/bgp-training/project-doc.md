خب، وارد بخش اصلی پروژه می‌شویم: **راه‌اندازی BGP و برقراری همسایگی بین ASها**.

در این مرحله می‌خواهیم R1 شبکه خودش را به R2 معرفی کند و این اطلاعات از طریق R4 به R5 برسد.

فعلاً R3 فقط یک روتر عادی است و هیچ مسیر جعلی اعلام نمی‌کند.

# **مرحله دوم: راه‌اندازی eBGP**

## **گام ۱. درک ارتباط Neighborها**

ابتدا این جدول را داشته باش:

| روتر | AS محلی | Neighbor       | Remote AS |
| ---- | ------- | -------------- | --------- |
| R1   | 100     | 10.0.0.2 (R2)  | 200       |
| R2   | 200     | 10.0.0.1 (R1)  | 100       |
| R2   | 200     | 10.0.0.6 (R4)  | 400       |
| R3   | 300     | 10.0.0.10 (R4) | 400       |
| R4   | 400     | 10.0.0.5 (R2)  | 200       |
| R4   | 400     | 10.0.0.9 (R3)  | 300       |
| R4   | 400     | 10.0.0.14 (R5) | 500       |
| R5   | 500     | 10.0.0.13 (R4) | 400       |

یک مفهوم مهم:

دستور `neighbor ... remote-as` به روتر می‌گوید:

«این IP متعلق به همسایه BGP من است و شماره AS آن فلان مقدار است.»

## **گام ۲. پیکربندی R1**

روی R1 وارد CLI شو و دستورات زیر را وارد کن:

```
enable
configure terminal

router bgp 100

neighbor 10.0.0.2 remote-as 200

network 130.130.130.0 mask 255.255.255.0

end
write memory
```

توضیح دستورات:

| دستور                             | کاربرد                           |
| --------------------------------- | -------------------------------- |
| `router bgp 100`                  | ایجاد فرایند BGP با AS شماره 100 |
| `neighbor 10.0.0.2 remote-as 200` | معرفی R2 به‌عنوان همسایه         |
| `network ... mask ...`            | اعلام شبکه اصلی R1 در BGP        |

**نکته مهم:** دستور `network` به BGP می‌گوید Prefix مربوطه را اعلام کند. این شبکه باید در Routing Table روتر وجود داشته باشد؛ در سناریوی ما به دلیل ساخت Loopback0، این شرط برقرار است.

## **گام ۳. پیکربندی R2**

حالا وارد CLI روتر R2 شو:

```
enable
configure terminal

router bgp 200

neighbor 10.0.0.1 remote-as 100

neighbor 10.0.0.6 remote-as 400

end
write memory
```

در اینجا R2 دو همسایه دارد:

- R1 با AS شماره 100
- R4 با AS شماره 400

فعلاً R4 را پیکربندی نکرده‌ایم؛ بنابراین طبیعی است که همسایگی دوم هنوز برقرار نشود.

## **گام ۴. بررسی اولین ارتباط BGP**

به R1 برگرد و دستور زیر را اجرا کن:

```
show ip bgp summary
```

دنبال IP همسایه `10.0.0.2` بگرد.

وضعیت مورد انتظار

باید وضعیت همسایه Established باشد.

در بعضی خروجی‌های Cisco به‌جای کلمه Established، در ستون `State/PfxRcd` یک عدد نمایش داده می‌شود. این عدد نشان‌دهنده تعداد Prefixهای دریافت‌شده است و خودش نشانه برقرار بودن Session است.

## **فعلاً همین‌جا توقف کن**

دو روتر R1 و R2 را تنظیم کن و خروجی دستور زیر را از R1 بفرست:

```
show ip bgp summary
```

بعد از بررسی خروجی، سراغ R4، R5 و R3 می‌رویم و کل شبکه BGP را تکمیل می‌کنیم.

**یادت باشد:** هنوز نباید روی R3 دستور `network 130.130.130.0 mask 255.255.255.0` اجرا کنی؛ این کار مربوط به مرحله شبیه‌سازی حمله است.
